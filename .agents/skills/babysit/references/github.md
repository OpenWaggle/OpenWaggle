# GitHub details for babysit

## Snapshot fields

`bun run pr:watch -- <pr>` prints one JSON object:

- `pr`: number, URL, state, `isDraft`, `headSha`, `reviewDecision`.
- `checks`: `failed` (required failures, or every failure when no check is required), `running`, `needsApproval`, `total`, `maxAttempts`. Check runs and commit statuses on the head commit are both counted.
- `bots`: Codex and Copilot review state, and `inProgress`, the bot reviews holding pushes back.
- `openItems`, `answeredThreads`, `warnings`, `canPush`, `signature`, `actions`.

Write commands below take a body file. Write the text to a file in the session scratch directory and pass `-F body=@<path>`, which reads the file, rather than putting long text on the command line.

## Replies

Every reply:

```markdown
> _This was generated by AI via the babysit skill._

<Fixed in <short sha>: what changed. | Not changed: the evidence. | The answer.>

<!-- babysit -->
```

A review thread (`reply.commentId` is the thread's first comment):

```bash
gh api --method POST "repos/{owner}/{repo}/pulls/<pr>/comments/<commentId>/replies" -F body=@reply.md
```

A conversation comment or review body: post a PR comment and add the item's `reply.marker` above `<!-- babysit -->`. List several markers to answer several items in one comment.

```bash
gh api --method POST "repos/{owner}/{repo}/issues/<pr>/comments" -F body=@reply.md
```

## What the watcher skips

- Your own comments that carry `<!-- babysit -->`, the AI notice, or any hidden `<!-- ... -->` marker. That covers the `pr:ready` blast-radius and review evidence comments.
- Bot comments with a hidden marker, deploy previews (Cloudflare Pages, Netlify, Vercel), the Codex summary comment and its usage-limit replies.
- Bot review bodies. Codex and Copilot post a receipt or overview as the review body and put their findings in inline threads, which are items.

## Codex

The Codex connector (`chatgpt-codex-connector[bot]`) reviews when a PR opens for review, leaves draft, or someone comments `@codex review`. It keeps one summary comment with a hidden `<!-- codex-review-state:v1 {...} -->` marker: `code_review.status`, `commit_sha` and `has_unresolved_findings`. It reacts 👀 on the PR while it works and 👍 when it found nothing. Findings arrive as inline threads with a P0 to P3 badge.

`bots.codex.status`:

- `running`: 👀 is on the PR, or the summary names the head with an unfinished status. Pushes wait.
- `stalled`: busy for more than 45 minutes. No longer holds pushes; report it.
- `findings` or `clean`: a finished review of the head.
- `usage_limited`: the review of the head failed with "You have reached your Codex usage limits". No bot review happened. Warn and do not wait.
- `failed`: the review of the head failed for another reason. Warn.
- `none`: no review of the head. Maintainers can turn automatic reviews off, so this does not block. `lastAttempt` shows the latest attempt on an older commit.

## Copilot

Copilot reviews are optional. While Copilot is a requested reviewer, `bots.copilot` is `requested` and pushes wait. Its findings arrive as inline threads like anyone else's.

## Reruns

`--rerun-job <id>` runs `gh run rerun --job <id>` for a failed check of the head commit, at most 3 attempts per job per SHA. `--force` lifts the limit once the maintainer agrees. GitHub refuses a job rerun while other jobs of the same workflow run are still running; wait for the run to finish.
