# Desktop shell

The desktop shell on Electrobun: the shell ports and their adapters, the trusted main network guard on Bun, hidden
QA and its non-disruption contract, packaged PATH, detached child handles, inline visualization frames and IPC
error shapes. Load when touching `src/main/index.ts`, the desktop shell ports, bindings or
`src/main/adapters/electrobun/`, window or trusted-origin code, packaging, or QA. Load
`.agents/memory/electrobun-webview.md` for the webview, RPC and loopback origins, and
`.agents/skills/electron-runtime/SKILL.md` as well.

## Desktop shell ports (ADR 0064)

- Main code reaches Electrobun only through the ports in `src/main/ports/desktop-shell/`, called through the bindings in `src/main/desktop-shell/`. Only `src/main/adapters/electrobun/` and `src/preload/transport.ts` import it (`openwaggle/desktop-shell-boundary`; see the table in `docs/hexagonal-architecture.md`). Tests mock the binding with the fakes in `src/main/test-support/fake-desktop-shell.ts` (`vi.mock('../desktop-shell/app-lifecycle')`); Vitest aliases the SDK to `scripts/test-support/electrobun-sdk-stub.ts`.
- An adapter must not import an app module that imports a binding, or it closes an import cycle back to itself that fallow reports. App policy goes in as a parameter instead: `MainWindowRequest.openLink` is `external-navigation.ts`'s `openExternalFromRenderer`.
- The boot shim has a size budget (`check:main-bundle`, 57 KB). Startup modules use `BootShell` (`desktop-shell/boot-shell.ts`), not the full bindings. Going through `AppPaths` once pulled in the logger, `env` and Effect, and boot.js grew to 556 KB. Keep loggers out of anything `electrobun-boot-shell.ts` imports.
- Port contract suites are data (`definePortContract`), not `describe` blocks, so `jest/no-export` allows them. Each case gets a fresh fake: `prepareElectrobunShell()` resets modules and installs `fake-electrobun.ts`, and the runner imports the adapter after that.

## Trusted main network guard on Bun (ADR 0064)

- Bun fixes a builtin's ESM named exports when it is first imported, and `syncBuiltinESMExports()` does nothing there. Patching `net.connect` on the module object missed `import { connect } from 'node:net'`, namespace and dynamic imports, and a trusted main extension opened a raw socket with no denial. Bun's `https.request` also calls the module-level `tls.connect`, so a patched `tls.connect` denied declared origins. Guard the shared objects every import style reaches on Node and on Bun: `net.Socket.prototype.connect`, `http.Agent.prototype.addRequest`, `ChildProcess.prototype.spawn`, `dgram.Socket.prototype`, the DNS `Resolver` prototypes, and the `worker_threads` `Worker` superclass (its `super()` calls the current prototype). An allowed request sets an AsyncLocalStorage target (`trusted-main-network-authorization.ts`) that lets only its own TLS socket and DNS lookup through.
- Bun-only paths sit on the `Bun` object, which `import { x } from 'bun'` reads, so `trusted-main-network-runtime-globals-guard.ts` wraps them there. `Bun.fetch`, `Bun.dns` and `Bun.WebView` are read-only and non-configurable, so `Bun.fetch` and `Bun.WebView` cannot be guarded. `Bun.dns`'s own members can be. Bun's `process` has its own native `on`/`once`/`off`, so `EventEmitter.prototype` patches miss it, and its `emit` does not rethrow a listener's error. Bun's `spawnSync` returns a thrown guard error in `result.error`.
- The residual risks (native code, shared-object mutation, ingress) are in the extension manifest docs. Closing them needs a separate process, not more in-process patches.

## Electrobun automation and packaging (November 2026)

- Scripts drive the app only through `scripts/support/electrobun-app-launch.ts` (hidden, CEF main window, `ELECTROBUN_CEF_REMOTE_DEBUGGING_PORT`), then `chromium.connectOverCDP` and the `/index.html` page. On a packaged macOS app the endpoint lists the renderer about 2.5 s after spawn. CEF keeps one process per `~/Library/Application Support/<identifier>/<env>/CEF` (not under `HOME`): launching a build that already runs logs `Opening in existing browser session` and exits 0. A copy with another `identifier` in `Contents/Resources/version.json` and `CFBundleIdentifier` runs beside it.
- A packaged app inside a checkout resolves modules missing from its own `Resources/app/node_modules` from the checkout's `node_modules`. The November 2026 builds missed `mammoth`, `jszip` and `unpdf` (bundled into main, but `attachment-parser-worker.ts` resolves them by path at load) and still booted in the checkout, while a copy elsewhere quit with `Cannot find module 'mammoth'`. Stage-node-modules now ships `RUNTIME_RESOLVED_PACKAGES`; test packaging bugs on a copy outside the checkout.

## Runtime and QA

- Packaged apps may not inherit a shell PATH. Pi package/resource loading and Pi-run child processes that shell out to tools need an adapter-controlled npm-compatible PATH, including common user tool dirs such as `~/Library/pnpm` on macOS.
- On macOS 26, `NSWorkspace.iconForFile` returns the icon as the Dock draws it, including the grey tile macOS puts behind icons that do not fill the rounded-square grid. Render a throwaway `.app` bundle holding a candidate `.icns` through it to check an icon without touching the Dock. The macOS icons come from `scripts/generate-macos-icons.ts` (Apple's 1024 grid: 824 px continuous-corner tile, 100 px margin); Windows/Linux keep the free-form mark.
- On Apple silicon, performance/package QA should use arm64 outputs, not Rosetta x64 output from a universal build folder.
- Agent-run QA has a hard non-disruption contract: the app must not show or focus a window, open a native dialog, or launch an external application. Automated paths fail instead of exposing OS UI; visible QA requires an explicit headed command.
- `bun run dev:debug` is the non-disruptive CDP automation entry point. Visible CDP QA is opt-in through `bun run dev:debug:headed`; `bun run dev` remains the normal visible development command.
- Hidden `bun run dev:debug` uses an ephemeral user-data directory and disables the single-instance lock. It must not focus an existing OpenWaggle process or read and write the normal development profile.
- Hidden agent QA owns CDP port 9223; port 9222 remains available for visible/manual debugging. The hidden launcher preflights 9223 and fails before launching the app if another process owns it.
- Hidden QA also requires a per-run identity in the renderer URL before accepting a CDP page. Port preflight alone is racy and must never be treated as proof that the connected process belongs to the launcher.
- The non-disruption contract is enforced inside the main process, not only by launch scripts. OS-visible shell actions go through an automation policy that fails closed, and repository standards reject new unguarded window-show/focus, native-dialog, and external-application call sites.
- Trusted-main and discovered Pi runtime extensions are not loaded during non-disruptive automation. Dynamically imported extension code cannot be brought inside the repository's static hidden-window construction boundary. Pi skills, prompts, themes, context, models, and auth metadata still load. Packaged Hive QA may explicitly retain host-supplied first-party inline factories so the native `hive` tool is exercised while discovered global/project extensions remain disabled.
- Agent-run headed QA requires the maintainer's explicit approval for that exact run. An agent cannot infer permission from a task needing native-UI coverage or from approval granted to an earlier run.
- The hidden-QA profile registers the current worktree as its selected project and starts with no fabricated sessions. Feature-specific tests or QA scripts add deterministic fixtures explicitly.
- Every scripted app launch is non-disruptive, including E2E, CDP QA, startup measurement, and website screenshot capture. The only visible paths are ordinary `bun run dev` and explicitly headed commands; agent use of any headed path still requires exact-run approval.
- Regression coverage proves hidden windows remain invisible and unfocused, guarded OS-UI calls fail, Playwright headed intent reaches the app, port conflicts fail before launch, managed cleanup removes the ephemeral profile, and repository checks reject new unguarded OS-UI call sites.
- Every completed agent-run QA captures representative screenshots from the hidden window, stores the evidence outside the repository, and renders the images in the final user response. QA evidence is never committed, and the repository has no visual-regression baselines (ADR 0033 removed them with the E2E suite).
- Linux launches forward an explicit parent `--no-sandbox` switch to the detached Session Host without disabling the sandbox by default. Bun's argv is `[runtime, script, ...args]` (`SCRIPT_ARGUMENT_OFFSET`); normalize only recognized leading runtime switches before the canonical command. Never search payloads for command words or remove application options. Startup QA records a bounded tail from the existing GUI stderr pipe and detaches on settlement, leaving detached Host stdio and lifetime independent.
- Detached QA Session Hosts can become unreachable zombies: `releaseQaLease` deletes the whole temp profile (including `host.sock`) while the Host outlives the QA client, which was observed as 10 idle `session-host-internal` processes (≈400MB each, hours old) with default Dock tiles. The Host now self-reaps when its endpoint socket file disappears (`watchUnadoptableSessionHostEndpoint`) and runs as an accessory process. Do not set the Dock icon at runtime: LaunchServices registers a second Dock tile on every packaged launch; packaged icon comes from the bundle's Info.plist. Those Hosts also never idled out before ADR 0047: the Host re-read the setting every second and `updateIdleGracePeriod` restarted the timer each time, and semantic discovery acquired and released a `semantic-preparation` owner every two seconds, which also restarted it. Only a changed value reschedules now, and `semantic-preparation` is idle-clock-neutral (it holds the Host while it works but does not reset the idle time). A Host from 1.0.0-beta.9 stayed up past 900 s idle; the fixed one exits at the 300 s grace.
- Playwright pointer delivery into a sandboxed iframe is not portable when the window is hidden: macOS can activate a framed button while Linux/Windows silently leave its handler untouched. For framed controls, dispatch the DOM activation inside the frame, assert synchronously that the handler entered its busy state, then poll a durable boundary such as the project-scoped extension-storage row. Main-renderer controls should keep using normal Playwright pointer actions, and the fixture unit test should cover transient banner text.
- A sandboxed custom-protocol iframe can self-navigate to a blank or failed document without delivering a reliable cancellable frame-navigation event. Inline visualizations therefore pair navigation guards with a post-load host-protocol health check and replace an unresponsive frame with a safe fallback.
- A parser-blocking visualization can prevent `load` entirely, so its deadline must be armed before assigning `src`. Authenticate the injected runtime with a credential-bearing bootstrap sent from the head before fragment parsing, but do not clear the deadline until a matching ready arrives at `DOMContentLoaded`; otherwise fragment code can win a first-ready race. Keep visualization sites out of process and use a low-frequency authenticated heartbeat for later silent navigation. Expiry should remove the isolated iframe; do not send an OS kill signal to its renderer, because macOS can surface that child-renderer crash as a crash of the containing Playwright page.
- Inline visualization Lucide loads asynchronously, but the skill tells fragments to call `lucide.createIcons(...)`, usually from their first synchronous render. Before the host runtime installed a queueing `window.lucide` placeholder, that threw a ReferenceError, the runtime reported `crashed`, and the whole visualization became "could not be loaded". Any uncaught fragment error still ends the frame, now with a script-failure message.
- Parked visualization frames (more than 400px off-screen) reload from their document, so a fragment reported its default state as the user's latest choice and the next turn's context regressed. Frames the user focused stay pinned (LRU of three), and every registration carries the source's last reported state as `restoredState`, surfaced to the fragment as `window.openai.visualizationState`.
- Inline visualization references are detected in two forms: the legacy private-use-delimited wire form (U+E200/`visualize`/U+E202 payload U+E201, matchable anywhere) and the delimiter-free bare form the visible skill template teaches (`visualize{"path":…}` alone on its line, strict payload parse). Authoring models cannot reliably reproduce invisible private-use characters, so never make a model-facing contract depend on them; the renderer streaming scan, the shared extractor, the ownership predicates (which run over serialized content JSON and must decode text parts first), and the snapshot SQL prefilter all cover both forms.
- A hidden screenshot failure does not authorize headed QA. The agent reports the incomplete evidence and asks for exact-run approval before using any headed fallback.
- CDP file upload can produce `File` objects without native paths; native file-path behavior needs preload/unit coverage or real OS selection QA.

## Filed under "Renderer polish from the beta.25 QA (#356, October 2026)"

- Show `ipcFailureMessage(cause, fallback)` (or `ipcErrorMessage`) for a failed invoke, never `cause.message` (it reads Electron's `Error invoking remote method` prefix and the Electrobun RPC's plain message). `shell:open-path`, `shell:reveal-path` and `shell:open-external` check the path or URL first and fail with words for the user, logging the system's reason; a non-disruptive automation block keeps its own message.
- The DevTools MCP writes `take_screenshot` files only inside its workspace roots (the checkout): save under `node_modules/.cache/` and copy to `$OPENWAGGLE_EVIDENCE_DIR`. `scripts/support/session-fixtures.ts` seeds Sessions and Hives into a running QA profile's Host database; reload the page to see them.

## Filed under "A dirty tree blocks checkouts"

`npx playwright test` does not build, and OpenWaggle no longer has a Playwright E2E suite (ADR 0033). `out/build-meta.json` still records the HEAD a build came from, and `scripts/record-build-meta.ts --verify` refuses a stale build (run `bun run build` first) — relevant for packaged-app QA via `bun run dev:debug` / `bun run packaged-app:smoke`.

CDP becoming reachable does not mean the app has created its renderer page: poll for the `/index.html` page target before asserting UI state, or a healthy restart fails intermittently.

Hidden Linux compositor timing is separate from background timer throttling: the full app produced roughly 1,016 ms animation-frame intervals under Xvfb with throttling off. Terminal performance QA subscribes to native presentation (about 16 ms frames), never replaces animation callbacks, reveals a window, or relaxes budgets. Fit the initial xterm viewport synchronously after `open()`, and keep the two-frame geometry gate before PTY spawn.
