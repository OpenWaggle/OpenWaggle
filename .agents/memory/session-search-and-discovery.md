# Session search and discovery

Finding Sessions: discovered Pi CLI sessions (ADR 0051), transcript-term and semantic
discovery (FTS5, vectors, backfill and ranking), and Settings > Archived items search.
Load when touching `pi-session-discovery*`, `sqlite-session-*search*`, semantic projection,
or the archived-items query.

## Settings > Archived items search (October 2026)

- The page reads one Host query (`sessions:query-archived-items`, Local Session revision 25) that returns a page, the total, and every Archive facet count in one SQLite statement: a MATERIALIZED `matched` CTE of archived sessions plus archived branches of active sessions, a `facets` row LEFT JOINed to the page (an empty page still brings one row of NULL item columns). Each facet counts with the other facets applied but not its own.
- Transcript search must not scan the transcript corpus. Each search word is matched as a prefix against `session_transcript_terms` through its `(session_id, term)` index, one archived session at a time, so cost follows the archive size; sessions without a `session_transcript_term_documents` row are stale (ADR 0037) and skipped. The excerpt reads the concrete indexed word and its `first_node_id` from that index, then runs one FTS5 `snippet()` with the exact quoted word on that row (`rowid = … AND MATCH "word"`). Never MATCH a prefix (`"f"*`): a `rowid` bound does not stop FTS5 merging the doclist of every word with that prefix, about a second per snippet on a large index, which blocks the Host's synchronous connection. The performance test covers a one-letter query over an 800,000-token index.
- SQLite `lower()`, `LIKE`, and `COLLATE NOCASE` fold only ASCII case, and a guess at case variants never covers mixed-case words such as "GrünÖl" or decomposed accents. Archived items search folds titles, parent titles, and project paths in JavaScript (`foldSearchText`: NFC, `toLowerCase`, `İ` to `i`), passes the per-term scores to SQL as JSON through `json_each`, and keeps only transcript matching in SQL; the renderer's highlighting folds the same way. The catalog filter's sub-trigram queries (one or two characters) try every lower/upper casing instead; FTS5 `trigram case_sensitive 0` and `unicode61` already fold Unicode.
- Bulk actions read each item's state first (`readArchivedItemStates`): restore and Undo skip items already in the requested state. A check once before a bulk delete is not enough: a 1,000-session batch takes minutes and a Hive follow_up can restore a Worker mid-batch. `sessions:delete-archived-sessions` sends each delete with `requireArchived`, which the Local UI delete checks before stopping the session's runs, again through `withSessionDesktopRemoval`'s `admit` inside the removal fence, and finally in the transaction that journals the deletion (`prepareSessionDeletion`). Restoring takes no removal fence, so `unarchive` and the Hive cleanup restore refuse while one is held (`refuseRestoreWhileRemovalFenced`); without that, a restore landing during the delete's teardown was deleted with it. It retries refused deletes while a pass still deletes something (a Queen is refused until its Workers are gone). Undo carries each item's earlier Archive time back (`setArchiveTimes`).
- `sessions.archived_at` (migration 69) is kept by a trigger on `UPDATE OF archived`, which copies the row's new `updated_at`, not by each writer. Writing the column from `persistOrganizationMutation` and `updateArchivedState` broke every hand-written `CREATE TABLE sessions` fixture that archives (Hive cleanup, organization repository tests); the trigger needs no fixture change.
- Bumping the Local Session revision means adding a `LOCAL_SESSION_REVISION_<n>_CAPABILITIES` entry and its literal in `schemas/local-session-negotiation.ts`, and updating the literal `[24]`/`revision: 24` expectations across `src/main/session-host/__tests__/local-session-*-revision.unit.test.ts`, the negotiation test's 16-entry revision list cap, the drain-admission read-only channel list, and the `sessions-handler` channel list.

## Filed under "Renderer And Session Memory"

- Discovered Pi sessions (ADR 0051, `application/pi-session-discovery.ts`): the Host polls every 10 s and lists `pi` CLI sessions whose header `cwd` is inside an OpenWaggle project (settings `projectPath`/`recentProjects`/`projectDisplayNames` plus non-archived Session projects; the most specific project wins). Pi's `SessionManager.list/listAll` stream every file in full (a real `~/.pi/agent/sessions` held 1,798 files, 2.1 GB), and `list()` also `mkdir`s the encoded directory, so the scanner (`adapters/pi/pi-session-discovery.ts`) filters directory names by Pi's `--<encoded cwd>` prefix, reads only a 64 KiB prefix of unknown files, confirms the header `cwd` (the encoding is ambiguous: `/a/b-c` vs `/a/b/c`), and remembers headers. Known means a `sessions` row by id/pi id/file or a `session_deletion_operations` row (the Session row is deleted before its Pi file). Each one is created through the Session lifecycle `create` (as `gui:local-user`, `workspace: local`, idempotency key `pi-session-discovery:<pi id>`, at most 100 per pass, newest first) so it gets the project Workspace binding, execution profile, and Session Control state like a desktop Session (rows inserted directly without them showed "This Session has no active Workspace" and "Follow-up queue unavailable" in QA); the still-unwritten Pi session the lifecycle created is then swapped for the discovered file and its times (`adoptDiscoveredPiSession`), with a discovery-chosen title (Pi `/name` or first message). Nodes are projected lazily on `sessions:get-detail`/`get-tree`/`get-workspace` and in the classic and Waggle preflights (`loadSessionForRun`). Freshness is a per-Session revision plus file size/mtime in `pi_session_file_projections` (migration 66), written in the same transaction as every repository `persistSessionSnapshot` and external projection (`persistPiSessionSnapshotWithSql`; the lifecycle fork path and tests that build schemas from the target schema use the plain `persistSessionSnapshotWithSql`, which does not record it): a changed fingerprint reads the file, an equal Pi entry count only records the new fingerprint (keeping the user's selected branch), and a different count re-projects through a compare-and-set on the revision under the Session lock, so a Run's snapshot always wins. Readers skip while any writer owns the Session. Adopted Sessions are marked in `pi_session_adoptions` (migration 65, which also adds `pi_session_dismissals`). A `pi` CLI fork copies its source's entry ids, which collided on the global `session_nodes.id` key (ADR 0041), and OpenWaggle never rewrites a file another program may hold open, so an adopted Session's nodes are its entry ids under `SessionDetail.piEntryNodeIdPrefix` (`<sessionId>/`). `agent-kernel/pi-entry-node-ids.ts` maps every id that crosses the Pi boundary: snapshot ids, parent ids, and the leaf; compaction `firstKeptEntryId`, branch-summary `fromId`, and label `targetId` in projected content; the `compaction_end` entry id; navigate and fork targets; the resume position; and an OpenWaggle fork's source node map. Deleting an adopted Session writes a dismissal in `prepareSessionDeletion` and leaves the file in place (no staged path). Discovery skips dismissed files and ids. An abandoned deletion removes its dismissal; a completed one keeps it, because the Session row is gone before the journal is dropped.
- Discovery review fixes (R5): files named by `session_lifecycle_preparation_attempts.pi_session_file` are known (scope and adopt transaction), and a file is listed only after a 5 s quiet period, because a fork's preparation writes the re-keyed file before recording it; adoption refused for a claimed file deletes the just-created Session. The lifecycle idempotency key is `pi-session-discovery:<pi id>:<size>:<mtime>`, and a replay naming a deleted Session is retried with a fresh key. Failed files back off in memory by size/mtime (1 min doubling to 1 h), and only successes count against the 100-per-pass cap. The scanner mirrors Pi's `readSessionHeader` (skip blank/malformed lines up to 1 MiB) and caches headerless files by size/mtime. Session directory resolution matches Pi's CLI: `PI_CODING_AGENT_SESSION_DIR` (read through `getEnvWithOverrides`, since `env.ts` is at its line limit), then `SettingsManager.create(cwd, getAgentDir()).getSessionDir()`; custom directories are flat and matched by header cwd, and `createPiSession`/`createSessionManagerForSession` create new files there. Viewing reads the file with `readFile` + `parseSessionEntries` + `SessionManager.inMemory`, which migrates old formats in memory only; `SessionManager.open` (Runs) rewrites them. Adopted Sessions store the header `cwd` (`pi_session_adoptions.cwd`, `SessionDetail.piSessionCwd`), which `resolveLocalWorkingPath` uses for local-mode Runs, and a reader's external projection applies the file's last model (if `ProviderService.isKnownModel`) and thinking level via `SessionSettingsRepository`. `sessions:delete` takes `{ removingProject: true }` from project removal: it pauses discovery for that project (in memory, until a pass finds the project gone or 2 min), and the local-ui `delete` command carries `removingProject` down to `SessionProjectionRepository.delete(id, { removingProject })` and `prepareSessionDeletion`, which for an adopted Session writes no dismissal and journals no Pi file to clean up, so no crash can leave the file dismissed. Session queries `read`/`turns`/`items` refresh first (`refreshBeforeSessionQuery`). A real Run in integration tests works against a local OpenAI-compatible SSE server registered in the temp agent dir's `models.json` (stub `HOME` so MCP and skills ignore the user's).
- Discovery round-2 fixes (R5/R6): non-Run kernel reads (`getContextUsage`, `getSessionSnapshot`) use `withReadOnlyPiSession`, an AgentSession over `SessionManager.inMemory(parseSessionEntries(file))` built with `createAgentSessionFromServices` and never `bindExtensions` (that is where `session_start` fires) and disposed with plain `dispose()`; opening the file as for a Run had migrated a v2 file to v3 and appended `thinking_level_change`. Discovery no longer imports `local-session-command-dispatcher` (that closed an import cycle through Host UI agent-definition modules into `runtime.ts`): `session-host-cli-entry` passes `createDiscoveredSessionWithLifecycle` into `runtime.startSessionHostOwnedServices`, and without it discovery does not run; tests pass it via `lifecycleCreate()`. Project removal calls `sessions:begin-project-removal` (revision 24; `sessions:delete` with its options argument is revision 24 too) before its deletion listing and refuses to drop project references if Sessions remain; discovery checks the pause before each create and in the adopt transaction (`isStillWanted`). Every listed id gets an `updated` notice. Continuation mirrors Pi's `getBranchSelection` (not exported): the last `model_change`, or the latest non-virtual response's model unless the previous `model_change` is virtual per `ProviderService.getProviderForModel(...).models[].virtual`; thinking is the branch's last `thinking_level_change`, else `SettingsManager.create(headerCwd, getAgentDir()).getDefaultThinkingLevel()` (project over global; `PiSessionFileSnapshot.defaultThinkingLevel`), else `ThinkingLevelDefaultService.getDefault()`, clamped with `clampThinkingLevel` to the continued (or current) model's `availableThinkingLevels`, as Pi's `createAgentSession` does (`buildSessionContext` reports `off` when there is no entry). Logic lives in `application/pi-session-continuation.ts`. Adoption sets `title_source` to `generated` (`default` for "New session"), and re-projection applies the latest `/name` through `SessionTitleRepository.applyGenerated` unless the title is `manual`. The scanner caches each file by size/mtime and forgets files no scan lists. Still open: a crash between Pi writing a fork file and `recordPreparedSessionFile` leaves a file discovery will list.
- Discovery round-3 fixes (R5): `resolveLocalWorkingPath` falls back to the cwd in the Session's own Pi file header (cached per file in `session-manager.ts`) when there is no `pi_session_adoptions.cwd`, so a fork or copy of a subfolder session, whose header keeps its source's cwd, runs in that subfolder. `getPiSessionSnapshot` projects `createReadOnlySessionManagerForSession` directly (or the warming session) with no AgentSession, because creating one appends a `thinking_level_change` when the branch has none; only context usage still builds an unbound AgentSession, for the model limits. Paused projects stay in the scanner's owner match and their sessions are filtered out, so a nested project's sessions do not move to the enclosing project mid-removal; after removal they do (Pi parity). A Session discovery drops runs the removal hooks and publishes `deleted`. Project removal never dismisses (see above); `undismiss` is gone from the discovery repository.
- Discovered-session titles and the Pi continuation choice (ADR 0051, October 2026). Pi 1.x records the whole system prompt as a `role: "system"` message entry with `sections` and `toolsAdded` (every tool schema, MCP tools too) before the first user message: 88-165 KB in real sessions, so the scanner's 64 KiB prefix found no first message and every recent `pi` CLI session was listed as "New session" and stayed so (nothing re-read known files). The prefix reader (`adapters/pi/pi-session-file-prefix.ts`) now reads up to 4 MiB when the prefix holds no user message and also returns the first message's time and the model change before it. A first-message title is adopted as `provisional` and asks `requestInitialSessionTitle` (with the file's model) when the message is under `TITLE_WORK_WINDOW_MS` old, else `generated`; each pass ends with `titleDiscoveredSessions` (`application/pi-session-discovery-titles.ts`), which re-titles adopted Sessions still `default` (or `provisional` and not yet requested this Host, as after a restart) from the scanner's cached `titleSource`. An external projection of an adopted Session triggers `requestSessionTitleRefinement`. Who wrote a file's latest prompt is derived from the file, not stored: every OpenWaggle user message is directly preceded by an `openwaggle-user-input` custom entry, and every Run starts with `openwaggle-run-boundary`; a user message without the former is from outside unless it follows a tool result or a `toolUse` reply (a steer into a running turn; Queen and user steers do lack the input entry). `adapters/pi/pi-session-prompt-origin.ts` scans incrementally from the last complete line (append-only files), `withPiSessionPromptOrigin` adds `SessionDetail.piSessionLastPromptOutside` to `sessions:get-detail` for idle Sessions (an optional DTO field, no Host UI revision; revision 24 already shipped, so a new channel would have needed 25). The composer gate (`usePiSessionContinuationGate`) re-reads the detail before sending in a discovered Session, asks, and on Keep running in pi opens the Session terminal with `pi --session '<file>'` typed but not run (`runSessionTerminalCommand({ submit: false })`) and rejects with `PiSessionContinuationHeld`, which `composerSendFailureDisposition` restores to the draft with a notice. The remembered choice is `settings.piSessionContinuationByProject` (resolved with the session-host settings because `snapshot.ts` is at its line limit).

## The embedding model is fetched on first use (November 2026)

The multilingual-e5 model is not packaged: the first embedding downloads the pinned revision from Hugging Face into `userData/models/session-embedding/<revision>/` (`session-embedding-model-files.ts`), checks every file against its pinned SHA-256, and until then search is lexical (readiness `preparing` or `unavailable` with `model` and `reason`, hybrid degrades with `semantic_not_ready`); a failed download retries after 15 s, doubling per failure up to 30 minutes.

## Filed under "Session Host authority and subscriptions are live boundaries"

Session semantic discovery keeps vectors only for the 100,000 most recently updated Sessions and
enforces the same limit in the resident exact index. A larger corpus is terminally `partial` once
that hot tier is prepared; hybrid discovery then uses the complete lexical index, while
semantic-only discovery may search the explicitly partial tier. Tier rotation must prune cold queue
rows and advance the deletion-compaction watermark so an evicted Session is neither re-embedded in
a loop nor retained by a stale resident snapshot.

Transcript term cutover must page with the three-column `(session_id, created_order, id)` tuple.
Expanding that comparison into OR predicates made SQLite rewind the node index for every 512-node
batch, producing quadratic prefix scans. Keep the production-query plan regression requiring an
indexed seek, along with tied-order and content-byte-boundary traversal coverage.

Batch document validation must start from the requested Session ids and left-join persisted
documents. An inner join let SQLite scan all 100,000 documents for every 512-node batch; the
left join also catches missing documents explicitly. Keep a temporary covering index on grouped
terms `(session_id, occurrences)` so per-Session token totals do not rescan every batch term.
Production-query plan regressions protect both boundaries without relaxing integrity checks.

Stage transcript terms by grouping FTS occurrences before looking up their previous persistent
counts. Joining the persistent term table first performed the same primary-key lookup once per
occurrence instead of once per distinct term/Session pair. Preserve the earliest node/Run evidence
and cumulative counts across batch boundaries; production-query instrumentation and a multi-batch
cutover fixture cover both. The paired production trial retained identical term, document, and
node-search rows with every cutover validation enabled.

Unscoped transcript-term ranking excludes the archived Session id set instead of looking up
the full Session row for every posting. Project and working-path filters still require that join;
authority and archive filtering must stay before the bounded ranking window. Exclude null ids
from the archive set so malformed legacy rows cannot poison SQL `NOT IN` semantics.

Discovery ranking reads Session id/archive metadata through the FTS5 content table's integer
rowid. SQLite documents `c0`/`c1` as the exact stored values of the first two FTS columns; this
avoids repeated FTS content callbacks without copying metadata or changing BM25 scores. Keep
that join read-only, preserve the FTS column order, and compare scores, ties, live mutations,
and pre-limit authority/archive filtering against the public FTS interface in regression tests.

Dense single-ASCII-token discovery can rank one native FTS representative per exact signature
of objective frequency, preview frequency, and total native token length. Do not copy BM25
arithmetic or persist scores: even equivalent arithmetic changed a score by one ULP. Bound the
signature probe and candidate work, retain native fallback for sparse/diverse signatures, and use
one SQL snapshot for admission, scoring, archive filtering, and the final Session-ID tie order.
Scoped, phrase, multiword, non-ASCII, and full-transcript requests retain their existing paths.

Discovery term postings follow the canonical discovery-row mapping through foreign-key cascades.
Incremental updates tokenize one document in a shared staging FTS inside the same transaction,
using the same native tokenizer. The staging table must be empty after success or rollback. A live
instance vocabulary filtered by document does not seek that document and would scan the entire
corpus per edit.
Migration 33 and legacy cutover group a single native vocabulary traversal, validate mappings
(including empty documents), postings and signatures, then install incremental triggers. Keep
schema revision 18 and the one-time cutover contract; existing targets apply migration 33 once.

Lexical evidence prepares query clauses and snippet terms once per result batch, lazily on the
first discovery match. Entirely ASCII input skips per-character Unicode normalization but retains
the same lowercasing and token regex. Mixed or non-ASCII text uses the original Unicode path;
do not broaden this fast path without token-sequence parity tests.

Node-delete search triggers must requeue semantic work only while the owning Session still
exists. During a Session cascade, the parent row is already gone; unconditional queue inserts
recreated a foreign-key dependency and made deletion preflight reject populated Sessions.
Migration 32 replaces that trigger in existing targets without repeating the legacy cutover or
changing schema revision 18. Standalone node deletion must still invalidate the surviving Session.

Semantic backfill must bound the ordered queue page before joining Session documents. Rebuilding
and sorting the entire hot tier for each 128-row batch made the 100,000-Session preparation exceed
its release budget. When the full corpus fits the tier, exact counts can bypass hot-tier joins;
evaluate that condition inside the same SQL snapshot and recheck membership after model inference
so a concurrent insertion cannot publish a newly cold Session.

Phrase search should retain its earliest matching node during the initial FTS scan. Rechecking
every candidate node repeats FTS posting traversal and scales with transcript length. SQLite's
single-MIN bare-column selection preserves the matching node here because Session created_order
is unique; keep the regression asserting earliest node/Run attribution and the query-plan guard
against correlated rowid-plus-MATCH re-probes.
