# Installing an update releases the Session Host

The detached Session Host runs from the app bundle, so macOS counts it as a running instance of OpenWaggle. Squirrel.Mac's installer waits for every instance to exit, checks again after verifying the update, and refuses with "App Still Running" if one is there. A Host left running by any install also keeps serving the old version's code to the new app. So every way of installing an update stops the Host the same way before the app is replaced: **Restart to update** in the app, `openwaggle update`, and the install script (`curl … | bash`).

All three send the `local-host-v1` stop that `openwaggle host stop` uses (ADR 0039), marked `purpose: 'update'`. The Host gives an update stop a 10-second deadline. At the deadline it interrupts any Run still active through normal cancellation, so it ends as interrupted, and gives Runs 3 more seconds to settle. Anything else still holding it, such as a running Action, a CLI wait, or an export, ends with the Host, as a restart ends it anyway. The answer to an update stop carries the Host's process id, and the installer waits up to 20 seconds for that process to exit (the deadline, the settle, and 7 seconds for the Host to shut down), because the Host closes its socket before the process is gone. An ordinary quit still leaves the Host running for background work.

Before the stop, each path handles active agent Runs the same way: wait for them to finish, stop them now, or cancel the update. Restart to update asks in the app before it quits. In a terminal, `openwaggle host stop --update` asks; the install script and `openwaggle update` run it. The install script quits the desktop window first, because stopping the Host under an open app only makes the app start another, then stops the Host, then replaces the app. If the user cancels, it reopens the app it quit and changes nothing. Without a terminal to ask on, it waits for the Runs, as Restart when idle does.

Where the desktop app waits differs by platform. On macOS it waits for the Host process. On Windows and Linux it only requests the stop: the NSIS installer closes leftover processes itself, and the AppImage updater starts the new version at once, so a longer quit only gets in the way. `openwaggle update` and the install script install only after the stop returns, so they always wait for the process. On Linux an open desktop app keeps running, and keeps its Host, until the user restarts it, as before; the CLI leaves a Host that an open desktop app owns alone.

The same investigation found that the Host never exited when idle. It re-read its idle grace setting every second and each read restarted the timer, and semantic discovery held it open for a moment every two seconds, which also restarted it. Only a changed setting now reschedules the timer. Semantic preparation still holds the Host open while it works, but no longer counts as activity, and it no longer shortens the startup grace or the client handoff grace.

Restart to update shows **Installing** at once and records the attempt. If the installer reports an error, or the app has not quit after 3 minutes, the update shows as ready again with the reason. Any quit the installer starts later, announced by Electron's `before-quit-for-update`, still releases the Host. On the next launch the app compares its version with the record. If the update did not install, it says so when that update is ready to install again, naming another running OpenWaggle process when macOS's installer log shows that was the reason. A newer update supersedes the old explanation.

## Considered options

- **Stop the Host in the installer, not the app.** Squirrel.Mac has no such hook, and killing the process marks every active Run `interrupted-by-host-loss`.
- **A stop with no deadline.** A dev server started as an Action never ends on its own, so the Host would never exit and the update would never install.
- **Tie the deadline to the desktop app's caller instead of a request field.** It worked with every Host that has the stop command, but the CLI paths of an update need the same bounded stop, and a caller rule cannot tell a CLI update from an ordinary `openwaggle host stop`. A Host older than the `purpose` field rejects it. The desktop app was refused by those Hosts anyway, so it quits and lets the next launch report the outcome; the CLI retries with a plain stop, which waits for the Host's work without a deadline. The process id is an optional response field that only update stops receive, so no older client ever decodes it.
- **Leave the install script and `openwaggle update` to the Host's own handover.** The Host only hands over when a newer app speaks a newer protocol revision, so after most updates the new app would keep the old version's Host, and on macOS a later Restart to update would still fail.
- **Stage the update with Squirrel as soon as it downloads**, so Restart to update quits at once (as VS Code does). Then any quit installs the update. An update installs only through one of three user actions: **Restart to update** in the app, `openwaggle update`, or the install script (`curl … | bash`). An ordinary quit is none of them, and Restart to update re-reads the Update channel just before it installs.

## Consequences

- ADR 0039 refused the desktop app's caller. It may now stop the Host, only for an update. The CLI may ask for an update stop too: that is the same person, who can already stop the Host, and named profiles and agents are still refused.
- A Run that starts while the update shows as installing, between Restart to update seeing no active Run and the Host's drain, is interrupted at the deadline instead of finishing. The drain refuses new Runs, so that window lasts only as long as macOS takes to unpack the update, and the app shows that it is restarting.
- An `openwaggle` command still running from the bundle, such as `openwaggle mcp serve` for another agent or `openwaggle sessions wait` in a terminal, still makes macOS refuse the install. The app reports it on the next launch instead of failing silently.
- Updating from a version without this change still runs that version's Restart to update or `openwaggle update`, which leave its Host running. The install script from this change stops an older Host with a plain `host stop --wait`, bounded to 20 seconds, so it works from those versions too. Users on them should run `openwaggle host stop --wait` before Restart to update, or quit and use the install script.
