# MCP Apps Reach the Origins Their Server Declares

Status: accepted

An MCP App is an HTML page a server attaches to a tool result (`_meta.ui.resourceUri`). Most real Apps are a stub that loads their code and styles from the server owner's CDN; Atlassian's Jira App is an empty `<div>` plus a script and stylesheet on `atlassian-mcp-micros.prod-east.frontend.public.atl-paas.net`. ADR 0013 said an App's network capabilities need an explicit grant, and the frame's Content Security Policy kept only declared origins that were also granted. ADR 0051 then removed grants: adding a server is the only trust decision. Nothing could grant an origin any more, so every CDN-loaded App rendered as an empty frame.

We decided that an App's frame may reach exactly the origins its server declares in the resource's `_meta.ui.csp` (`resourceDomains`, `connectDomains`, `frameDomains`, `baseUriDomains`, as the MCP Apps spec maps them to CSP directives). This follows ADR 0051: the user trusted the server when they added it, and the server already chooses what its tools do. The App keeps every other boundary of ADR 0013: a sandboxed, opaque-origin `allow-scripts` frame with no Electron, Node, storage, or device access; tool calls, links, and messages it asks for still go through confirmation; and it reaches nothing it did not declare. A declaration is used only when it is an http(s) or ws(s) origin, optionally with a `*.` subdomain wildcard, a port, and a path; a bare `*`, CSP keywords, schemes such as `data:`, or text that would end the directive are dropped, so a server chooses its origins but not the shape of the policy.

The policy only works if the App document has its own. A `srcdoc` frame inherits OpenWaggle's page CSP, which allows no scripts from the network, so a declared CDN still could not load. Each App document is therefore served by the Host from its own origin, `openwaggle-mcp-app://frame-<uuid>/document`, with the declared policy as its `Content-Security-Policy` header, built in the main process from the declarations (sanitized again there, so the renderer cannot widen it). The frame is `sandbox="allow-scripts allow-same-origin"`: same-origin only with its own unique frame origin, never with OpenWaggle, because Apps read cookies and IndexedDB, which an opaque origin refuses (Atlassian's App throws without them). Because the frame is same-origin with whatever it loads, it may not be navigated off its document: the main process blocks such frame navigations (`shouldBlockMcpAppFrameNavigation`), and the page's own `frame-src` refuses any other origin before that. That origin's storage is cleared when the frame goes, so nothing an App stores outlives its frame, which keeps ADR 0013's "persistent storage needs a grant".

The frame also follows the App's data: it starts 1 px high with a "Starting MCP App…" line, takes the height the App reports for its content (48–800 px; taller content scrolls inside the App), gets 320 px if it runs without reporting a size, and is replaced by a note when the App has not finished its handshake within 15 s. The frame's width and the theme are sent to the running App as host context changes, so it lays its data out again when the panel is resized or the theme changes. The theme is read from OpenWaggle's appearance (`data-theme`); light and high-contrast light are `light`, the rest `dark`.

Considered and rejected: keeping the grant list and adding a per-server grant UI (a second trust decision ADR 0051 removed, for a capability the server already declares), and proxying App network traffic through the Host (more surface, and Apps load from CDNs that already send `Access-Control-Allow-Origin: *`). Consequence: an App can send what it shows to the origins its server declared; that is the same trust the user already gives the server's tools.
