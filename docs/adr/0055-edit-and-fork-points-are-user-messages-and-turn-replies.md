# Edit and Fork Points Are User Messages and Turn Replies

Status: accepted

The transcript offers to branch or copy a conversation at two kinds of point only: a **user message** and a settled turn's **reply** (the last assistant message of the turn a user message started, when it answered in text and called no tool; a step a steer or an interruption cut short, and a failed response, are not replies). Each Waggle agent turn has a reply of its own. A user message offers **Edit from here** (a branch in this Session before the message, its text back in the composer) and **Fork from here** (a new Session before the message, its text in the composer). A reply offers **Continue from here** (a branch in this Session after the reply), **Fork from this response** (a new Session holding the conversation through the reply, with an empty composer), and **Copy response** (its text). A reply's actions sit at the end of the whole turn, under its text and its changed-files card, not after the folded work above it; the transcript's last reply shows them, earlier ones on hover. `/fork` and the command palette's Fork to new session choose a user message; `/clone` copies the whole conversation shown. Fork from this response is a copy at the reply's node, as a clone is at the head, so its new Session is titled `(copy)` like a clone's; a fork before a user message is titled `(fork)`.

Tool results, the assistant text written between tool calls, and branch summary cards no longer carry a branch button. They are steps of a turn, not places people return to, and a button on every tool row made each turn a column of identical branch icons. The Session tree still reaches every point of the history, including tool results, for whoever needs one.

While the Host holds a Session, from a send until its Run settles, the transcript offers no branch or copy: the Host would refuse them. (`/fork`, `/clone`, the palette, and the sidebar stay available and say the Session is busy.) A reply's bar keeps its place with only Copy response, so sending does not move the transcript above the new turn. A turn that is still running has no reply yet, even while a steer the agent has not read renders after it. A reply has no View turn diff of its own: the changed-files card at the end of its turn opens the diff (ADR 0034), folded or expanded, in a Waggle agent turn too.

This follows T3 Code, which offers "Edit from here" on each user message and Copy and "Fork from this response" on each completed turn's last assistant message, moved below the turn's trailing work, and nothing on tool calls. We keep a Pi-style fork before a user message, which T3 Code lacks, because a retry of a prompt in a new Session is the copy people already make with `/fork`.

Considered and deferred: forking a settled reply while a later turn runs, as T3 Code allows. A copy only reads its source, but the copy's Pi runtime starts extensions under the source's Session id, and the MCP companion would attach and then detach the running Session's MCP context. Starting that runtime under the new Session's id is the prerequisite.
