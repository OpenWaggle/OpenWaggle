# Split MIT packages from a GPL-3.0 app, with a lightweight CLA and a trademark notice

Date: 2026-11-16

OpenWaggle shipped with no root LICENSE file: the app was all-rights-reserved by default, while the four `@openwaggle/*` npm packages each already shipped an MIT `LICENSE` — attributed to `Copyright (c) 2026 OpenWaggle`, a project name that is not a legal person and can therefore hold no copyright. Research for Windows code signing made the gap blocking: the free option, the SignPath Foundation, requires an OSI-approved license, and the maintainer's requirement was that the code stay open and contributable while the app's rights — trademark, commercial licensing, and the ability to accept investment, offers, or sponsorship — remain the maintainer's alone. The decision, made with the maintainer over a grilling session, is a split license plus two supporting instruments: a lightweight Contributor License Agreement and a trademark notice.

## Decision

- **MIT for `packages/`, GPL-3.0 for everything else.** The four `@openwaggle/*` packages (`extension-sdk`, `extension-react`, `waggle-core`, `pi-waggle`) are MIT, honoring the license they already declared and shipped; their existing `LICENSE` files are re-attributed from `OpenWaggle` to the Project Owner, Diego Garcia Brisa, the only party who could hold the copyright. The rest of the repository — the app, its build tooling, and the website — is GPL-3.0 (`GPL-3.0-only`, SPDX), under the root `LICENSE`. The MIT boundary keeps the extension ecosystem free: third-party extensions built against the MIT SDK keep any license they choose, and the GPL app's copyleft stops at that boundary.
- **GPL-3.0 for the app because the maintainer holds the rights.** The maintainer's stated priority is holding the app's rights over maximizing adoption. GPL-3.0 makes a proprietary fork of the app impossible without a commercial exception, and only the Project Owner can grant one: that is the lever for any future investment, offer, or sponsorship, enforced by copyright rather than by brand goodwill. GPL restricts distribution, not use, so corporate *use* of the app is unaffected.
- **A lightweight CLA, not a DCO, not assignment.** [CLA.md](../../CLA.md) has contributors keep their copyright while granting the Project Owner (Diego Garcia Brisa *and that person's successors and assigns*, so the grants travel with any future entity) a perpetual, irrevocable license including relicensing and commercial terms. A DCO grants nothing beyond the inbound license and would prevent selling exclusive rights; full assignment maximizes friction for no additional commercial benefit. The single pre-existing external commit (`7ee5fc373`, a `.fallowrc.jsonc` trim) touches only a lint config and is de minimis.
- **Code PRs are open, and acceptance is by submission, enforced by CLA Assistant.** This decision also opens code pull requests (CONTRIBUTING.md): submitting a Contribution means accepting the CLA, and [CLA Assistant](https://cla-assistant.io/) — the standard one-time-signature GitHub App for exactly this lightweight, in-repo CLA shape, and the pattern every major CLA project (VS Code, Angular, Zulip) uses through one signature plus a merge-blocking status check — enforces it. A PR-template checkbox was rejected as the wrong idiom (that is DCO/issue-triage practice; no major CLA project uses it). The maintainer connects the App to the repository and points it at `CLA.md`; a PR without the status cannot merge.
- **A trademark notice, Ghost-style.** [TRADEMARKS.md](../../TRADEMARKS.md) states that the name, wordmark, logos, and visual identity are the Project Owner's trademarks, unlicensed by MIT or GPL-3.0, and that forks must rename. Verified practice (Ghost's README policy, VS Code, Zulip): the statement is standard; the file placement is this repo's most discoverable in-repo form. With GPL holding the code and the CLA holding the commercial rights, the trademark holds the identity.
- **Windows signing follows the license.** SignPath Foundation (free, OSI now satisfied) is the signing path: application pending, artifacts stay unsigned until accepted, matching the existing rule that Windows signing does not block `1.0.0`. Azure Artifact Signing ($9.99/month) is the future upgrade when affordable, accepted as the one-time SmartScreen certificate-reputation reset that any signer switch costs. EV certificates are not a path: Microsoft's SmartScreen documentation states EV no longer bypasses SmartScreen, so the premium buys nothing here.

## Considered options

- **One license for the whole repo.** Rejected: it would either break the published MIT declaration of the four packages or drag the extension SDK into copyleft, strangling the extension ecosystem at birth (ADR 0066 makes the SDK the public API).
- **MPL-2.0 for the app.** Rejected: file-level copyleft lets a competitor ship the inherited files open inside a closed product, leaving the moat to the trademark alone. GPL-3.0 moves the protection into the license itself.
- **A source-available license (FSL, BSL, PolyForm).** Rejected: not OSI-approved, which closes the free SignPath Foundation signing path the decision was made to enable.
- **Copyright assignment instead of a CLA.** Rejected: more friction, no additional commercial benefit over the grant-and-relicense CLA.
- **Self-signed Windows certificates.** Rejected: same SmartScreen wall as unsigned, no reputation path.

## Consequences

- Only the Project Owner may license proprietary or commercial versions of the app. Anyone else distributing it must stay GPL-3.0 with source, under a different name.
- Extensions and packages built against `@openwaggle/extension-sdk` are unaffected by the app's copyleft and may carry any license.
- The four packages' `LICENSE` files now name the copyright holder who can actually hold it; the root gains the GPL-3.0 text the app never had.
- Code PRs are open: CONTRIBUTING.md links the CLA, and the `main` ruleset enforces the gate. `license/cla` (CLA Assistant) is one of seven required status checks, and it carries only the pre-existing repository-admin bypass that keeps an emergency default-branch change possible. **No ruleset requires an approving review.** A separate `OpenWaggle approvals` ruleset briefly required one approval plus a code-owner review; it locked the Project Owner out of their own pull requests, because GitHub never counts an author's own approval and the ruleset's bypass actor did not clear the requirement, so a single write-capable account can never satisfy it. It was removed the same day. Sole write access already enforces the intent: an outside contributor cannot merge, so every pull request lands through the Project Owner's review or not at all. `.github/CODEOWNERS` stays to route a review request to them, and a review rule returns when a **second** person holds write access, at which point a maintainer can approve the Project Owner's pull requests and the requirement becomes satisfiable. Requiring `license/cla` also means `github-actions[bot]` must be allowlisted in CLA Assistant, or the release pull requests stay blocked.
- Switching Windows signers later (SignPath → Azure) resets SmartScreen reputation once, weighed then against the signing cost; macOS signing is unaffected.
